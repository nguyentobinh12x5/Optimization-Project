\paragraph{Zero-return diagnostic.}
Beyond the two vendor defects described in \cref{sec:data}, the per-ticker proportion of
exactly-zero return sessions was ranked across all 98 tickers. The purpose was diagnostic: a
single ticker dominating the zero counts would indicate a per-ticker feed problem --- a stock
suspended from trading, or a symbol whose price series is stale --- which is a different defect
requiring a different remedy from the market-wide repeated-price artifact that the $90\%$
filter targets. No such dominance was found; zero returns are distributed across tickers at
levels consistent with ordinary low-liquidity sessions and price-limit days on an exchange with
daily price bands.

\paragraph{Why the holiday filter is statistical.}
A \texttt{dayofweek >= 5} test removes weekends but cannot remove Vietnamese public holidays
that fall on a weekday. Hard-coding a holiday calendar would require annual maintenance and
would fail silently once out of date. The implemented rule --- drop any session on which at
least $90\%$ of tickers post exactly zero return --- keys on the observable signature of the
defect rather than on the calendar. The threshold is deliberately high: genuine market-wide
flat days are possible in principle, and a lower threshold risks discarding real sessions. As
noted in \cref{sec:data}, this filter removes no rows from the present panel.

\section{The Joint Proximal Operator}\label{app:prox}

This appendix gives the proof of \cref{prop:jointprox} and the full algorithm statement.

\subsection{Proof of \texorpdfstring{\cref{prop:jointprox}}{Proposition 1}}

\begin{proof}
The objective is strongly convex and the constraint affine, so the minimizer exists, is unique,
and strong duality holds. Introduce a multiplier $\nu$ for the budget constraint:
\[
  L(w,\nu) = \tfrac12\norm{w-z}_2^2 + t\norm{w}_1 - \nu\bigl(\one^\top w - 1\bigr)
           = \sum_{i=1}^{N}\Bigl[\tfrac12 (w_i - z_i)^2 + t|w_i| - \nu w_i\Bigr] + \nu .
\]
For fixed $\nu$ the Lagrangian \emph{separates across coordinates}: each bracketed summand
involves only $w_i$. Completing the square in the smooth part,
\[
  \tfrac12 (w_i - z_i)^2 - \nu w_i
  = \tfrac12\bigl(w_i - (z_i + \nu)\bigr)^2 - \nu z_i - \tfrac{\nu^2}{2},
\]
so minimizing the $i$-th summand is exactly evaluating the scalar proximal operator of
$t|\cdot|$ at the shifted point $z_i + \nu$, whose closed form is soft thresholding:
$w_i(\nu) = \softt_t(z_i + \nu)$.

It remains to choose $\nu$ so that the primal constraint holds, that is, to solve $h(\nu) = 0$
where $h(\nu) = \sum_i \softt_t(z_i+\nu) - 1$. Each map
$\nu \mapsto \softt_t(z_i + \nu)$ is continuous and non-decreasing, hence so is $h$; moreover
$h(\nu) \to \pm\infty$ as $\nu \to \pm\infty$, since for $|\nu|$ large every coordinate is
outside the threshold band and $h$ grows linearly with slope $N$. A root therefore exists.
There is no closed form for it --- $\softt_t$ is piecewise linear with a flat segment, so
$h$ is piecewise linear with data-dependent breakpoints --- and the implementation locates the
root by bracketing it through geometric expansion of an initial interval and then bisecting to
a tolerance of $10^{-12}$ on $|h(\nu)|$. Substituting $\nu^\star$ back into
$w_i = \softt_t(z_i + \nu^\star)$ gives the claimed minimizer, which is unique by strong
convexity.
\end{proof}

\subsection{The full algorithm}

\begin{figure}[htbp]
\centering
\begin{minipage}{0.95\textwidth}
\begin{lstlisting}[language={}, basicstyle=\ttfamily\footnotesize, numbers=none,
                   frame=single]
Input:  mu_hat, Sigma, Sigma^(1/2), kappa, gamma, lambda,
        alpha_0 = 10, max_iter = 5000, tol = 1e-8, patience = 100
w_0      <- (1/N) * 1                     # feasible start: 1'w = 1
best_obj <- +infinity
stall    <- 0

for k = 0, 1, 2, ..., max_iter - 1:
    r <- ||Sigma^(1/2) w_k||_2
    s <- (Sigma w_k) / r   if r > eps   else   0        # robust subgradient
    v <- -mu_hat + 2*gamma*(Sigma w_k) + kappa*s        # subgradient of f
    alpha <- alpha_0 / sqrt(k+1)                        # step size
    z <- w_k - alpha*v                                  # subgradient step
    w_{k+1} <- JointProx(z, t = alpha*lambda)           # Proposition 1
    f <- objective(w_{k+1})
    if f < best_obj:
        rel <- |best_obj - f| / max(|best_obj|, tiny)
        best_obj <- f;  best_w <- w_{k+1}
    stall <- stall + 1  if rel < tol  else  0
    if stall >= patience: break                         # converged

return best_w, best_obj

JointProx(z, t):                                        # Proposition 1
    bracket nu in [-1, 1], expanding geometrically until
        h(nu_lo) <= 0 <= h(nu_hi),  h(nu) = sum_i S_t(z_i + nu) - 1
    bisect on nu until |h(nu)| < 1e-12
    return S_t(z + nu*)                    # exact zeros where |z_i+nu*| <= t
\end{lstlisting}
\end{minipage}
\caption{The proximal-subgradient method of \cref{sec:method}. \texttt{S\_t} denotes
coordinate-wise soft thresholding at level $t$. The only nontrivial step is
\texttt{JointProx}; replacing it with soft thresholding followed by a separate projection onto
$\{\one^\top w = 1\}$ reintroduces the bug analysed in \cref{sec:proxbug}. For the long-only
variant of \cref{sec:backtest}, \texttt{JointProx} is replaced by Euclidean projection onto the
probability simplex and the $\lambda$ argument disappears.}
\label{alg:proxsub}
\end{figure}

\section{Full Cross-Verification Results}\label{app:verification}

\Cref{tab:cvxpyfull} is the complete comparison summarized in \cref{tab:cvxpy}. The additional
columns are $f_{\text{cvx}}$, the objective attained by CVXPY/CLARABEL; $\ell_\infty$, the
largest absolute difference between corresponding weights of the two solutions; the iteration
count of the hand-written solver; and its convergence flag.

The $\ell_\infty$ column is worth a comment, because it is the one place the two solutions
differ visibly. The largest weight discrepancy, $1.65 \times 10^{-2}$, occurs for
$(\kappa,\gamma,\lambda) = (0, 5, 0.1)$ --- the sparsest and slowest-converging case, at 2113
iterations. Even there the objective gap is $7.75 \times 10^{-6}$ relative and the active sets
are identical. This is the expected signature of a first-order method halted at a finite
tolerance on a problem whose objective is flat near the optimum along certain directions: the
optimal value is pinned down far more precisely than the individual coordinates that attain it.

\section{Reproduction}\label{app:repro}

\begin{lstlisting}[language={}, basicstyle=\ttfamily\small, numbers=none, frame=single]
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m src.data_loader     # only if data/*.parquet is absent
pytest tests/ -v              # 40 passed
python -m nbconvert --to notebook --execute notebook_en.ipynb \
       --output notebook_en.ipynb
\end{lstlisting}

The test suite comprises \textbf{40 tests, all passing}, covering the estimators (symmetry,
positive semidefiniteness, square-root reconstruction, shrinkage bounds), the solver
(feasibility, exact sparsity, monotonicity of the best objective, simplex projection
properties, the closed-form mean--variance limiting case), the CVXPY cross-check, and the
backtest (absence of look-ahead in the window construction, turnover accounting, benchmark
correctness). The notebook executes end to end in roughly 50 seconds from the cached parquet
files, with no network access.

The first data download is the only step requiring network access and takes considerably
longer, on the order of tens of minutes, because the free tier of the data API is rate limited
and each of the 98 tickers is fetched separately. Results are cached to
\texttt{data/prices.parquet} and \texttt{data/returns.parquet}, so it is run once.
